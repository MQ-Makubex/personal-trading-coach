# Separate mode-validation state and artifacts

Mode-validation state will have its own local SQLite database at `state/mode_validation.sqlite`, while immutable run cards and artifacts will live under `reports/mode_validation/<mode_id>/<version>/<run_id>/`. The existing `state/account_ledger.sqlite` remains the owner of sanitized trade facts only, and `state/trading_modes.json` remains the owner of mode definitions, versions, and overall human-assigned mode status. Site generation joins these sources read-only and deploys only audited, sanitized projections; raw research artifacts are never part of the deployed site bundle. All validation and review writes remain local in v1 through the loopback-only, ephemeral-token-protected visual workbench service. Validator jobs are persisted for observability but execute through one serial local queue; job concurrency never creates a second writer. The deployed variant has no write controls, write API, or cloud database connection. A whole-mode review does not mutate `trading_modes.json` immediately: the workbench renders the exact before-and-after diff, requires a second confirmation, records the pre-write hash and review event, and performs an atomic write with full rollback on failure.
