# Separate the coach desk from research execution

The personal trading coach will keep the `个人交易教练台` as a private, evidence-driven presentation and review surface, while data retrieval, validation, backtesting, and agent research run through a separate `本地研究执行器`. This preserves the site's narrow privacy and safety boundary while allowing richer research capabilities without exposing credentials, raw trading data, or code-execution surfaces through the deployed site. The same mode-validation workbench has two runtime surfaces in v1: a local visual surface enables proposition verdicts, review notes, run invalidation, and confirmed execution of registered validators, while its deployed Cloudflare build hides every write control and remains read-only. Validator execution is allowlisted by stable validator id and fixed parameter schema; the workbench never accepts arbitrary shell commands, Python paths, or natural-language code execution. Each execution shows a preview before confirmation, freezes the applicable contracts, creates a new run id, and emits an immutable run card. Registered validators share a single execution queue: reads and previews may run concurrently, but only one validator executes at a time; queued work may be cancelled and running work may only receive a safe-stop request. The local HTTP service binds only to `127.0.0.1`; every write request requires an in-memory random startup token and a valid loopback Origin, and the token is never placed in static files, URL query strings, or persistent browser storage. Closing the local workbench session or stopping the service removes write capability. Local changes become visible online only after static regeneration. No cloud write API, research database, or raw validation artifact is exposed by the deployment; CLI review commands are secondary testing and recovery tools rather than the primary user experience.
